# Дизайн-система и экраны WEBAPP
## HackAlem AI — Автоматизация формирования заказов поставщикам

Дополняет [ARCHITECTURE.md](./ARCHITECTURE.md) и [FRONTEND_TZ.md](./FRONTEND_TZ.md). Акцентный цвет **`#2c7294`** (тёмный сине-бирюзовый) — вся палитра ниже посчитана и провалидирована от него (OKLCH-модель, WCAG-контраст, CVD-безопасность для дальтоников), а не подобрана на глаз.

---

## 1. Принципы дизайна

- **B2B рабочий инструмент, не витрина.** Плотная, но читаемая информация: таблицы, цифры, бейджи — приоритет над декоративностью.
- **Прозрачность важнее красоты.** Раз ключевое требование ТЗ — explainability, любое число в интерфейсе должно быть кликабельно/раскрываемо до обоснования.
- **Нейтральный фон, акцент — только для действия и идентичности.** Акцентный цвет используют кнопки, ссылки, активные состояния и выделение выбранного `calc_run` — не заливки целых блоков.
- **Светлая и тёмная темы равноценны** — обе посчитаны отдельно, ни одна не «автоинвертирована».

---

## 2. Цветовая схема

Основа — модель OKLCH: цвет проверяется по формуле (не «на глаз») скриптом `validate_palette.js` из дизайн-системного метода — контроль полосы светлоты, порога насыщенности, разделения для дальтоников (CVD ΔE) и контраста к фону. Все значения ниже прошли проверку.

### 2.1 Акцент (бренд) — роли и состояния

| Роль | Light | Dark | Контраст |
|---|---|---|---|
| `accent-solid` (кнопки, primary CTA) | `#2c7294` | `#1477a0` | белый текст на кнопке: 5.33:1 (light) / 5.03:1 (dark) — норма AA |
| `accent-hover` | `#01678e` | `#2686b1` | — |
| `accent-active` | `#00597d` | `#01678e` | — |
| `accent-text` / ссылки | `#2c7294` | `#50a6d2` | 5.19:1 / 6.41:1 на фоне поверхности |
| `accent-subtle-bg` (бейджи, выбранная строка) | `#cff1ff` | `#003c57` | — |
| `accent-subtle-text` (текст на subtle-bg) | `#01678e` | `#cff1ff` | 5.31:1 / 9.91:1 |
| `accent-focus-ring` | `#2c7294` | `#3995c1` | компонентный контраст к фону ≥ 3:1 |

**Важно:** в тёмной теме кнопка красится не в чистый `#2c7294`, а в `#1477a0` — иначе белый текст на кнопке проваливает контраст (3.36:1 вместо нужных 4.5:1). Разработчикам не подменять токены вручную.

### 2.2 Нейтральная палитра (холодный, слегка бирюзовый серый — в тон акценту)

| Роль | Light | Dark |
|---|---|---|
| `page-bg` (фон страницы) | `#f6fbfe` | `#090e11` |
| `surface` (карточки, таблица, drawer) | `#fbfeff` | `#151b1f` |
| `border` (разделители, рамки) | `#d7e0e5` | `#272f34` |
| `text-primary` | `#0b1317` (18.8:1) | `#f6f9fa` (16.4:1) |
| `text-secondary` | `#45555e` (7.7:1) | `#b5bfc5` (9.3:1) |
| `text-muted` (плейсхолдеры, иконки, вспомог. подписи — НЕ для основного текста) | `#7b8990` (3.6:1) | `#768289` (4.4:1) |

### 2.3 Статусные цвета (фиксированные, не тема — не путать с акцентом)

| Роль | Hex | Правило использования |
|---|---|---|
| `good` | `#0ca30c` | Всегда иконка + подпись, не только цвет |
| `warning` | `#fab219` | Всегда иконка + подпись |
| `serious` | `#ec835a` | Всегда иконка + подпись |
| `critical` | `#d03b3b` | Всегда иконка + подпись |

**Смысловая привязка для домена заказов:**

| Домен-концепт | Значение | Токен |
|---|---|---|
| Срочность = высокая | дефицит близко/уже наступил | `critical` |
| Срочность = средняя | требует внимания | `warning` |
| Срочность = низкая | остаток в норме | `good` |
| Статус = ожидает | дефолтное состояние, не проблема | нейтральный бейдж (`border` + `text-secondary`), НЕ статусный цвет |
| Статус = утверждено | | `good` |
| Статус = отклонено | | `critical` |

### 2.4 Категориальная палитра для графиков (идентичность серий)

Для графиков с несколькими рядами (например, сравнение категорий товаров). 8 слотов, порядок фиксирован — слот 1 образован от акцентного оттенка (H≈233°), остальные — из валидированного дефолтного набора метода. Проверено скриптом: полоса светлоты ✓, порог насыщенности ✓, разделение для дальтоников (худшая соседняя пара ΔE 9.1 light / 8.4 dark, порог 8.0) ✓, contrast-relief требуется для слотов 3/4/5 (см. ниже).

| Слот | Оттенок | Light | Dark |
|---|---|---|---|
| 1 | brand-blue | `#2686b1` | `#3995c1` |
| 2 | orange | `#eb6834` | `#d95926` |
| 3 | aqua | `#1baf7a` | `#199e70` |
| 4 | yellow | `#eda100` | `#c98500` |
| 5 | magenta | `#e87ba4` | `#d55181` |
| 6 | green | `#008300` | `#008300` |
| 7 | violet | `#4a3aa7` | `#9085e9` |
| 8 | red | `#e34948` | `#e66767` |

Слоты 3 (aqua), 4 (yellow) и 5 (magenta) в светлой теме дают контраст < 3:1 к поверхности — обязательны видимые прямые подписи значений или табличный вид рядом с графиком (не полагаться на цвет).

**Для 3 и меньше рядов на графиках типа scatter/bubble** (где сравниваются все пары точек, а не только соседние) используйте только первые 3 слота — они дополнительно проверены на все взаимные пары.

### 2.5 Последовательная (sequential) палитра — для одного показателя

Для тепловых карт, графиков динамики спроса одного SKU, индикаторов заполненности буфера — один оттенок (тот же, что и акцент), светлота от светлого к тёмному:

| Шаг | Hex | Шаг | Hex | Шаг | Hex | Шаг | Hex |
|---|---|---|---|---|---|---|---|
| 100 | `#cff1ff` | 250 | `#81c8ef` | 400 | `#3995c1` | 550 | `#01678e` |
| 150 | `#b7e6ff` | 300 | `#66b7e1` | 450 | `#2686b1` | 600 | `#00597d` |
| 200 | `#9ed8f9` | 350 | `#50a6d2` | 500 | `#1477a0` | 650 | `#004a69` |
| | | | | | | 700 | `#003c57` |

Для **непрерывной** магнитуды (heatmap) используйте весь диапазон 100→700 — светлый край может «уходить» в фон. Для **дискретных** уровней (например, 4 уровня заполненности буфера) не берите шаг светлее **300** (`#66b7e1`, 2.17:1 к светлой поверхности) и не темнее **600** (`#00597d`) в тёмной теме — иначе крайний шаг перестаёт читаться как метка.

### 2.6 Правила применения (обязательны к соблюдению)

1. Цвет из этого документа — единственный источник правды. Никаких «на глаз» подобранных hex в коде компонентов.
2. Категориальные оттенки назначаются рядам **в фиксированном порядке** и никогда не перециклируются, если рядов больше 8 — сворачивать в «Остальное».
3. Статусные цвета не переиспользуются как «ряд 4» на графике и наоборот.
4. Текст всегда на нейтральных токенах (`text-primary/secondary/muted`), не на цвете серии — идентичность несёт маркер/бейдж рядом.
5. Тёмная тема — не автоинверсия, а собственный набор значений выше; переключение темы фиксируется на уровне страницы, темы не смешиваются в одном экране.
6. При изменении палитры — прогнать `validate_palette.js` заново (команда в `references/color-formula.md` дизайн-скилла), а не менять hex вручную.

## 3. Типографика и сетка

- Шрифт: системный стек `system-ui, -apple-system, "Segoe UI", sans-serif` — без загрузки веб-шрифтов (соответствует требованию минимума зависимостей).
- Числовые колонки таблиц (количество, остаток, срочность-индекс) — `font-variant-numeric: tabular-nums`, чтобы цифры выравнивались по разрядам.
- Крупные KPI-цифры на дашборде — обычные пропорциональные цифры, не табличные.
- Сетка отступов — кратно 4px (4/8/12/16/24/32).
- Радиусы скругления: 24–28px для основных панелей и карточек, 16px для кнопок, полей, навигации и вложенных карточек, 999px для бейджей-пилюль. На узких экранах боковая навигация располагается над контентом.

## 4. Базовые компоненты (`shared/ui/`)

| Компонент | Варианты |
|---|---|
| `Button` | primary (`accent-solid`), secondary (outline, `border`+`text-primary`), destructive (`critical`), ghost |
| `Badge` | urgency (critical/warning/good), status (neutral/good/critical), category (нейтральный) |
| `Table` | сортируемые заголовки, сворачиваемые группы (по поставщику), чекбоксы строк, sticky header |
| `Drawer` | боковая панель (обоснование по SKU), закрытие по Esc/клику вне |
| `Modal` | подтверждение массового действия (approve) |
| `KPI Tile` | заголовок + крупное число + дельта (стрелка/цвет через статусные токены) |
| `ChartCard` | обёртка графика: заголовок, легенда, переключатель периода, состояние загрузки |
| `Select / Combobox` | фильтры (поставщик, категория, срочность) |
| `Toast` | успех/ошибка операций (approve, export, сохранение настроек) |

## 5. Экраны приложения

### 5.1 Login (заглушка авторизации)
- Центрированная карточка на `page-bg`: логотип/название системы, поле логина, поле пароля, кнопка `accent-solid` "Войти".
- Без соцавторизации/сложных флоу — это mock на этапе MVP.

### 5.2 App Shell (общий каркас, на всех экранах)
- **Sidebar** (слева, фиксированный): пункты навигации Заказы / Дашборд / Настройки, активный пункт подсвечен `accent-subtle-bg` + `accent-text`.
- **Header** (сверху): название компании-партнёра, селектор `calc_run` (дата и статус последнего расчёта, выпадающий список истории прогонов), кнопка "Пересчитать" (`accent-solid`), иконка пользователя/выход.
- **Content area**: белая/поверхностная зона под конкретный экран.
- Тема light/dark переключается из header (иконка солнце/луна), сохраняется в localStorage.

### 5.3 Orders — экран рекомендованных заказов (главный)
- **Панель фильтров** (одна строка под header): мультиселекты «Поставщик», «Категория», «Срочность», «Статус» + поле поиска по артикулу/наименованию + счётчик "Показано N из M".
- **Панель массовых действий** (появляется при выборе чекбоксов): "Утвердить выбранные", "Экспортировать выбранные", счётчик выбранных строк.
- **Таблица**, сгруппированная по поставщику (сворачиваемые секции с подытогом кол-ва строк):
  - чекбокс
  - Артикул (код 1С + артикул поставщика, второй — приглушённым `text-secondary`)
  - Наименование
  - Категория (бейдж нейтральный)
  - Рекомендуемое количество
  - Утверждённое количество (редактируемое поле инлайн)
  - Срочность (`Badge` urgency)
  - Статус (`Badge` status)
  - Кнопка-иконка "Открыть обоснование" (→ Drawer 5.4)
- **Пагинация/виртуализация** внизу таблицы.
- **Кнопка экспорта** (верхний правый угол): выбор формата CSV/Excel/PDF в dropdown.
- Пустое состояние: иллюстрация-заглушка + текст "Нет рекомендаций по выбранным фильтрам" + кнопка сброса фильтров.

### 5.4 Order Detail Drawer — карточка обоснования (explainability)
Открывается справа поверх Orders при клике на строку/иконку.
- Заголовок: наименование + артикул, кнопка закрытия.
- Текстовое обоснование (`narrative`) — выделенный блок сверху, крупным читаемым текстом.
- **Разбивка факторов** (список "фактор → значение", не JSON): базовый спрос, коэфф. сезонности, коэфф. роста, компенсация stockout, буфер безопасности — каждая строка с мини-подписью, что она значит.
- **Блок остатков**: текущий остаток / зарезервировано / свободный остаток / товар в пути — 4 мини-плитки в ряд.
- **Список исключённых разовых/оптовых заказов**: таблица (дата, документ, объём) с пояснением "не учтено в расчёте регулярного спроса".
- **Форма корректировки**: поле "Утверждённое количество" (предзаполнено рекомендуемым), поле комментария, кнопки "Утвердить" (`accent-solid`) / "Отклонить" (destructive outline).
- Предупреждение под кнопками: "Утверждение не отправляет заказ поставщику автоматически" — текст на `text-secondary`, не скрыт.

### 5.5 Dashboard — аналитика
- **Ряд KPI-плиток** (4 шт.): всего позиций к заказу, позиций с высокой срочностью (бейдж critical), число поставщиков в текущем расчёте, дата последнего расчёта.
- **ChartCard "Тренд спроса"**: линейный график `actual_qty` vs `forecast_qty`, переключатель SKU/категории сверху, легенда снизу.
- **ChartCard "Сезонность"**: bar-график коэффициентов по месяцам (sequential-палитра, один показатель).
- **Виджет "Риск дефицита"**: список топ-N позиций высокой срочности (переиспользует `Badge` urgency), клик — переход в Orders с применённым фильтром.
- Адаптивная сетка: KPI в ряд, графики 2 колонки на desktop, 1 колонка на планшете.

### 5.6 Settings — параметры расчёта
- **Секция "Параметры прогноза"**: форма — горизонт прогноза (дней, number input), буфер безопасности (дней), чувствительность к выбросам (слайдер 0–1 с подписанными краями). Кнопка "Сохранить" + "Запустить пересчёт" (`accent-solid`).
- **Секция "Правила поставщиков"**: таблица (поставщик, SKU, min_order_qty, order_multiple, lead_time_days) с инлайн-редактированием ячеек.
- Валидация полей — подсветка ошибки `critical` цветом рамки + текст под полем.

### 5.7 Общие состояния (для всех экранов)
- **Loading**: скелетоны таблиц/графиков (не спиннер на весь экран).
- **Empty**: единый паттерн — иконка, короткий текст, действие (сброс фильтров / создать первый расчёт).
- **Error**: инлайн-баннер `serious`/`critical` с текстом ошибки и кнопкой "Повторить", не блокирующий весь экран модалкой.
- **Toast**: правый нижний угол, авто-скрытие через 4с, ручное закрытие, статусные цвета для успеха/ошибки.
- **Confirm dialog** (массовое approve): заголовок, текст с количеством позиций, явная фраза про отсутствие автоотправки, кнопки "Отмена" / "Утвердить".
