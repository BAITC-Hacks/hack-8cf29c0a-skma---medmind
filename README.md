# HackAlem AI

Система формирования рекомендованных заказов поставщикам для ТОО «Электрокомплект». Помогает менеджеру закупок оценить потребность в товаре, проверить обоснование, скорректировать количество и вручную утвердить заказ.

**Утверждение не отправляет заказ поставщику автоматически.**

## Как работает система

1. Backend загружает Excel-файлы IEK и Systeme Electric через отдельные адаптеры поставщиков.
2. Расчёт учитывает историю продаж, остатки и резервы, товары в пути, сезонность, рост спроса и условия поставки.
3. Для каждого SKU формируется рекомендуемое количество с учётом минимальной партии (MOQ) и кратности заказа.
4. Frontend показывает рекомендации по поставщикам, срочность, факторы расчёта и исключённые аномальные отгрузки.
5. Менеджер проверяет позиции, корректирует количество, утверждает рекомендации и экспортирует результат.

Данные и история расчётов хранятся в **SQLite**. Отдельный сервер базы данных не требуется.

## Текущее состояние

| Часть | Реализовано |
|---|---|
| Заказы | Полный CRUD позиций: создание из каталога, карточка, редактирование, удаление с подтверждением; фильтры, группировка, сортировка, пагинация и мультивыбор |
| Обоснование | Факторы спроса, остатки, товар в пути, исключённые отгрузки, корректировка количества и комментарий |
| Утверждение | Одиночное и массовое, с предупреждением об отсутствии автоотправки |
| Экспорт | CSV в интерфейсе; CSV и XLSX через backend API |
| Аналитика | Два графика, четыре KPI и список рисков на демонстрационных данных |
| Интерфейс | Светлая/тёмная тема, общая навигация, выбор исторического расчёта |
| Backend | Импорт Excel, расчёт, REST API, настройки параметров и правил поставщиков |
| Входные данные | Backend CRUD для товаров и источников расчёта; CSV/XLSX-импорт с preview и загрузка ZIP-комплектов поставщиков |

Проект находится в разработке. Ограничения текущей версии:

- Экран настроек — заглушка; параметры пока доступны через API.
- Дашборд использует собственные синтетические данные даже при подключённом backend; его показатели не сверены с таблицей заказов.
- Кнопка «Пересчитать» в интерфейсе отключена. Запуск доступен через CLI или `POST /api/calc-runs`.
- PDF-экспорт и авторизация пока не реализованы.

## Стек

- **Frontend:** React 19, TypeScript, Vite, React Router, TanStack Query, Tailwind CSS, Recharts, React Hook Form.
- **Backend:** Python, FastAPI, SQLAlchemy, pandas, NumPy, openpyxl, python-calamine.
- **База данных:** SQLite, режим WAL. По умолчанию — `backend/var/hackalem.db`.
- **Зависимости:** npm для frontend, uv для backend.

## Запуск в Docker (рекомендуется)

Нужен Docker Engine с Compose v2 или Docker Desktop в режиме Linux containers.
Node.js, Python и uv на компьютере устанавливать не нужно. Из корня репозитория:

```bash
docker compose up --build -d
```

Откройте [http://localhost:8080](http://localhost:8080).
API доступно через тот же адрес: [проверка состояния](http://localhost:8080/api/health),
[Swagger](http://localhost:8080/docs). При первой сборке нужен интернет для загрузки
образов и зависимостей; первый старт включает загрузку встроенного снимка данных.

Compose запускает два контейнера: Nginx с собранным frontend и FastAPI backend.
Frontend собирается с `VITE_USE_MOCK=false`, запросы `/api` проксируются к backend.
Как и при обычном запуске, отдельные страницы пока используют локальные демоданные.
В пустую базу автоматически загружаются встроенные тестовые данные без прогнозов;
существующие данные при перезапуске не заменяются. SQLite, вложения ассистента
(в базе) и экспорты сохраняются в Docker-томе `app-data`, в том числе после
`docker compose down`. Локальная база `backend/var` в контейнер не копируется.

Обычный запуск не требует `.env`. Для другого порта, отключения сидера или
включения ИИ-ассистента скопируйте **корневой** `.env.example` в `.env`
(`Copy-Item .env.example .env` в PowerShell, `cp .env.example .env` в Bash).
Укажите `APP_PORT`, `SEED_ON_START=false` или `OPENAI_API_KEY` и примените:

```bash
docker compose up -d
```

В Docker используются настройки корневого `.env`; `backend/.env` и
`frontend/.env.local` не включаются в образы. Без `OPENAI_API_KEY` остальные
функции работают, ассистент недоступен. По умолчанию порт открыт только на
локальном компьютере (`127.0.0.1`).

Полезные команды:

```bash
docker compose ps
docker compose logs -f
docker compose exec backend hackalem calc
docker compose down
```

`hackalem calc` запускает отдельный расчёт и создаёт прогнозы по данным в базе.
Для импорта отчётов можно загрузить ZIP через интерфейс или скопировать папки
поставщиков в контейнер и выполнить CLI:

```bash
docker compose cp ./reports/. backend:/app/var/imports/
docker compose exec backend hackalem ingest
docker compose exec backend hackalem calc
```

В `reports` должны лежать папки IEK и Systeme electric с исходными отчётами.
`ingest` заменяет исходные данные поставщиков; для обычного демозапуска он не нужен.
После изменения кода повторите `docker compose up --build -d`.
Команда `docker compose down -v` **удаляет базу и экспорты** — используйте её
только для намеренного полного сброса.

## Требования для запуска без Docker

- Node.js **22.18+** и npm.
- Python **3.12+** и uv; командой `uv sync --python 3.12` можно создать окружение на Python 3.12.
- Для обновления данных из отчётов — исходные Excel-файлы партнёра. Для сидера, деморежима frontend и тестов они не нужны.

Команды ниже выполняются из корня репозитория, если не указано другое. Примеры копирования файлов приведены для PowerShell; в Bash вместо `Copy-Item` используйте `cp`. Файлы окружения копируйте только при первом запуске, чтобы не перезаписать свои настройки.

## Быстрый запуск: frontend без backend

```powershell
cd frontend
npm ci
Copy-Item .env.example .env.local
npm run dev -- --port 5173 --strictPort
```

Откройте [http://localhost:5173](http://localhost:5173). В `frontend/.env.local` должно быть:

```dotenv
VITE_USE_MOCK=true
VITE_API_BASE_URL=/api
```

Деморежим заказов использует вымышленные данные. Решения по заказам сохраняются при переходах между страницами в текущей сессии; перезагрузка страницы восстанавливает фикстуры.

**Ассистент всегда работает через backend и реальные модели OpenAI**, независимо от `VITE_USE_MOCK`.
Для `/assistant` запустите backend с `OPENAI_API_KEY` в `backend/.env`; Vite в dev/preview проксирует `/api`
на `http://127.0.0.1:8000`. Диалоги и загруженные файлы сохраняются в SQLite, анализ использует серверные данные.
Без backend или ключа интерфейс покажет недоступность ассистента. Для production настройте reverse proxy `/api`
или задайте `VITE_API_BASE_URL` при сборке. Ключ нельзя помещать в переменные `VITE_*`.

## Запуск с backend и SQLite

Для развертывания тестовых данных выполните **одну команду из корня репозитория**:

```powershell
uv run --directory backend hackalem seed
```

Команда создаёт SQLite-базу и таблицы и загружает сохранённый в репозитории снимок текущих данных:
3 905 товаров, 248 915 строк продаж, остатки, поставки, справочники, настройки и 4 899 заказов.
Excel-файлы и `DATA_DIR` для этого не нужны. Используется `DATABASE_URL` из `backend/.env`
(по умолчанию `backend/var/hackalem.db`).

**Прогнозы (`sku_forecasts`) не входят в сидер, расчёт не запускается.** История расчётов сохраняется
для связи с заказами; подробные обоснования и прогнозные ряды появятся после отдельного `hackalem calc`.
Повторный `seed` пропускает уже установленный снимок и сохраняет последующие изменения.
Если база уже заполнена другими данными, команда завершится без изменений: для тестового развертывания
укажите отдельную пустую базу в `DATABASE_URL`. Затем запустите `uv run --directory backend hackalem serve`.

Сидер наполняет серверную базу. Для заказов из неё установите `VITE_USE_MOCK=false`;
отдельные локальные демоданные страниц товаров, истории продаж и дашборда не переключаются этой командой.
Подробности и обновление снимка — в [backend/README.md](backend/README.md#тестовые-данные-сидер).

### 1. Установить зависимости backend

В первом терминале из корня проекта:

```powershell
cd backend
uv sync --python 3.12
Copy-Item .env.example .env
```

Отредактируйте `backend/.env`:

```dotenv
DATA_DIR=../../docs-hackalem/docs
DATABASE_URL=sqlite:///./var/hackalem.db
EXPORT_DIR=./var/exports
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

`DATA_DIR` должен указывать на вашу папку с исходными файлами, например `C:/data/hackalem`. Внутри нужны папки поставщиков, названия которых содержат `iek` и `systeme` без учёта регистра:

```text
<DATA_DIR>/
  IEK/
    ... Excel-файлы поставщика
  Systeme electric/
    ... Excel-файлы поставщика
```

Адаптеры рассчитаны на структуру исходных отчётов партнёра: динамику продаж, остатки, MOQ, товар в пути и сезонность. Произвольная Excel-таблица вместо этих отчётов не подойдёт.

### 2. Загрузить данные и выполнить расчёт

Из папки `backend`:

```powershell
uv run hackalem ingest
uv run hackalem calc
uv run hackalem serve --reload
```

`ingest` полностью перезагружает исходные данные поставщиков, включая правила MOQ; ручные изменения этих правил будут потеряны. Команда нужна при первичной загрузке или обновлении исходных файлов, а не при каждом запуске сервера.

Каталог базы и таблицы создаются автоматически. Команды backend запускайте из `backend/`: относительные пути в `.env` считаются от рабочей директории.

После первоначальной загрузки для обычного запуска достаточно:

```powershell
uv run hackalem serve --reload
```

- API: [http://127.0.0.1:8000/api](http://127.0.0.1:8000/api) — префикс маршрутов.
- Проверка сервера: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health), ожидаемый ответ — `{"status":"ok"}`.
- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Без Excel-файлов загрузите тестовые данные командой `uv run hackalem seed` вместо `ingest` и `calc`.

### 3. Подключить frontend

Во втором терминале из корня проекта:

```powershell
cd frontend
npm ci
```

Создайте `frontend/.env.local` из `.env.example`, если его ещё нет, и установите:

```dotenv
VITE_USE_MOCK=false
VITE_API_BASE_URL=http://127.0.0.1:8000/api
```

```powershell
npm run dev -- --port 5173 --strictPort
```

Откройте [http://localhost:5173/orders](http://localhost:5173/orders) и выберите завершённый расчёт в шапке. После изменения `VITE_*` перезапустите Vite. Если используете другой порт frontend, добавьте его origin в `CORS_ORIGINS` и перезапустите backend.

## Методология расчёта

- Аномальные разовые отгрузки определяются по объёму строки документа относительно распределения продаж SKU: используются медиана, MAD и порог относительно месячного объёма. Для редких SKU применяется отдельное правило. Исключения сохраняются для объяснения результата.
- Спрос корректируется с учётом периодов отсутствия товара по месячным снимкам остатков.
- Базовый спрос строится по последним 12 полным месяцам с поправками на сезонность и тренд роста.
- Потребность покрывает срок поставки и горизонт планирования, добавляет страховой запас, вычитает свободный остаток и товар в пути, затем округляется по MOQ и кратности.
- Срочность определяется по ожидаемому исчерпанию запаса относительно поступления поставки.

Методология и ограничения исходных данных описаны подробнее в [backend/README.md](backend/README.md). Валидация против ручного эталона пока не завершена: есть расхождения между источниками продаж, требующие уточнения у партнёра. Формула frontend-моков служит только для демонстрации интерфейса и не заменяет серверный алгоритм.

## Проверки и сборка

Frontend, из `frontend/`:

```powershell
npm test
npm run lint
npm run build
npm run preview
```

Сборка создаётся в `frontend/dist`. `preview` запускает локальный просмотр сборки; адрес выводится в терминале. Для подключения этого адреса к backend добавьте его в `CORS_ORIGINS`. Значения `VITE_*` включаются при сборке: после их изменения нужно повторить `npm run build`.

Backend, из `backend/`:

```powershell
uv run pytest
uv run ruff check src tests
```

Backend-тесты используют синтетические данные и отдельную временную SQLite-базу, файлы партнёра им не нужны.

