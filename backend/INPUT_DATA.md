# Входные данные: ручной CRUD и импорт из 1С

API работает с теми же таблицами SQLite, которые читает расчётный движок. После изменения входных данных запустите новый расчёт (`POST /api/calc-runs` или `uv run hackalem calc`): существующие результаты автоматически не пересчитываются.

Интерактивные схемы запросов доступны в Swagger: `http://127.0.0.1:8000/docs`, группы `input-data` и `imports`. Авторизация в проекте пока отсутствует; сервер по умолчанию слушает только `127.0.0.1`.

## Ручное создание, чтение, редактирование и удаление

Для каждого ресурса доступны:

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/input-data` | Список ресурсов, ключи и JSON Schema |
| GET | `/api/input-data/{resource}` | Список: `items`, `total`, `limit`, `offset` |
| POST | `/api/input-data/{resource}` | Создать запись, ответ 201 |
| GET | `/api/input-data/{resource}/{key}` | Получить запись |
| PUT | `/api/input-data/{resource}/{key}` | Заменить запись полным объектом |
| DELETE | `/api/input-data/{resource}/{key}` | Удалить запись без каскадного удаления |

| Ресурс | Данные | Ключ URL |
|---|---|---|
| `suppliers` | Поставщики и сроки поставки | `id` |
| `categories` | Категории и множитель страхового запаса | `id` |
| `products` | Товары: код 1С, артикул, наименование, единица, поставщик, категория, себестоимость | `code` |
| `sales` | Строки продаж/возвратов | Числовой `id` из ответа |
| `stock-monthly` | Остатки на первое число месяца | `sku_code~YYYY-MM-DD` |
| `stock-current` | Текущий остаток, резерв и сублокации | `sku_code` |
| `transit` | Товары в пути, заказ и ожидаемая дата | Числовой `id` из ответа |
| `supplier-rules` | Минимальная партия и кратность | `sku_code` |
| `seasonality` | Выручка поставщика по месяцам | `supplier_id~year~month`, например `iek~2026~9` |
| `reference-metrics` | Эталонные показатели ручного расчёта | `sku_code` |

Списки поддерживают `limit` (1–500, по умолчанию 50), `offset`, фильтры `sku_code`, `supplier_id`, `category_id` для ресурсов с соответствующими полями. `search` ищет по наименованию, коду, артикулу или документу там, где они есть. Неподдерживаемый фильтр возвращает 422.

Ключи строковые; ведущие нули сохраняются. В ключах нельзя использовать `/`, `\` и `~`. Изменить ключ через PUT нельзя. Поля, отсутствующие в полном PUT, получают значения по умолчанию — это не PATCH.

### Пример ручного ввода

Сначала создайте поставщика и категорию:

```http
POST /api/input-data/suppliers
Content-Type: application/json

{"id":"manual","name":"Новый поставщик","lead_time_days":14}
```

```http
POST /api/input-data/categories
Content-Type: application/json

{"id":"cable","name":"Кабель","buffer_multiplier":1}
```

Затем товар:

```http
POST /api/input-data/products
Content-Type: application/json

{"code":"000123","supplier_id":"manual","supplier_sku":"ART-1","name":"Кабель 3×2,5","unit":"м","category_id":"cable","unit_cost":250.5}
```

И остаток:

```http
POST /api/input-data/stock-current
Content-Type: application/json

{"sku_code":"000123","as_of":"2026-09-23","on_hand":100,"reserved":20,"locations":{"Основной склад":100}}
```

`free` вычисляется сервером (`on_hand − reserved`) и не принимается от клиента. `locations` — информационная разбивка; расчёт использует итоговые `on_hand`, `reserved`, `free`.

### Валидация и связи

- Поставщик, категория и товар должны существовать до создания связанных записей.
- Поставщик строки поставки или правила MOQ должен совпадать с поставщиком товара.
- Отрицательные остатки, резерв больше остатка, NaN/Infinity, нулевая кратность, неверные даты и неизвестные поля отклоняются.
- Дробные количества поддерживаются. В `sales` положительное количество означает отгрузку, отрицательное — возврат; ноль запрещён. `doc_type` по умолчанию — `Расходная накладная`, этот тип читает расчётный движок.
- Даты — ISO (`YYYY-MM-DD`), время продажи — местное время без часового пояса.
- Удаление справочника с зависимостями возвращает 409 с перечнем таблиц. Товар, использованный в расчёте, удалить нельзя. Смена поставщика товара со связанными данными также запрещена.
- Во время расчёта новый CRUD/импорт возвращает 409. Параллельные записи сериализуются SQLite; при конфликте блокировки можно повторить запрос.
- Создание, изменение и удаление журналируются в `audit_log` с исходными и новыми значениями. Новый импорт не запускает отправку заказов поставщику.

## Универсальный импорт CSV/XLSX

`POST /api/input-data/{resource}/import`, `multipart/form-data`:

| Поле формы | Значение |
|---|---|
| `file` | CSV или XLSX |
| `dry_run` | `true` по умолчанию: проверка без сохранения; `false`: применить |
| `options` | JSON-объект параметров, по умолчанию `{}` |

Параметры `options`:

```json
{
  "mapping": {"Код 1С":"code","Наименование":"name","Артикул":"supplier_sku"},
  "defaults": {"supplier_id":"manual","category_id":"cable","unit":"м"},
  "source": "1c-main",
  "header_row": 1,
  "encoding": "utf-8-sig",
  "delimiter": ";"
}
```

`mapping` задаёт **заголовок файла → поле API**. Если mapping задан, остальные колонки игнорируются; без него все заголовки должны совпадать с полями API. Отсутствующие/пустые значения берутся из `defaults` либо проверяются по схеме. Записи импортируются как полные объекты: необязательные поля, не переданные при повторном импорте, могут сброситься к значениям по умолчанию.

Поддерживаются UTF-8 (с BOM и без), Windows-1251 (`encoding=cp1251`), разделители `;`, `,`, табуляция. XLSX читает первый лист или лист по имени `sheet`. Заголовок можно указать через `header_row` (1–100). Даты CSV принимаются также как `ДД.ММ.ГГГГ` и `ДД.ММ.ГГГГ ЧЧ:ММ:СС`; десятичная запятая и пробелы в числах нормализуются.

Коды, артикулы и номера документов в Excel должны быть **текстовыми ячейками**: числовая ячейка могла уже потерять ведущие нули, поэтому такие идентификаторы отклоняются. Формулы в импортируемых полях запрещены; выгружайте значения.

Лимиты: 20 МБ на файл, 50 000 строк, 100 колонок; большие выгрузки делите на части. Пустые строки пропускаются. Для произвольных XML/CommerceML и XLS адаптер пока не реализован.

### Повторные загрузки

- Товары обновляются по коду 1С; справочники, остатки и правила — по ключам из таблицы ресурсов.
- Для `sales` и `transit` требуется дополнительная колонка `external_id`: стабильный идентификатор **строки** из 1С, например GUID документа + номер строки. Один номер документа недостаточен.
- Пара `(source, external_id)` уникальна в рамках ресурса. Повторная загрузка обновляет существующую строку, а не добавляет копию. Между перезапусками сервера связи сохраняются в SQLite (`import_identities`).
- Повтор ключа внутри одного файла считается ошибкой. Отсутствующие в файле записи не удаляются.
- Если записи ранее созданы вручную без внешнего идентификатора, новый импорт продаж/поставок не угадывает совпадения по документу и количеству. Не импортируйте тот же набор параллельно двумя способами.

Пример CSV продаж:

```csv
external_id;sku_code;ts;document;qty
document-guid:1;000123;23.09.2026 10:00:00;000045;12,5
```

### Ответ и атомарность

```json
{
  "resource": "products",
  "dry_run": true,
  "applied": false,
  "total_rows": 3,
  "created": 2,
  "updated": 1,
  "unchanged": 0,
  "errors": [],
  "errors_truncated": false
}
```

При ошибках ответ 422 содержит отчёт в `detail`, с номерами строк и причинами (максимум 100 ошибок). **Любая ошибка отменяет весь файл**, включая аудит и привязки идентификаторов. В preview и при ошибках счётчики описывают проверенные строки, а не сохранённые записи. Для записи повторите запрос с `dry_run=false`; сервер заново проверит актуальные связи в БД.

## Импорт исходных архивов партнёра

Для комплектов из предоставленных ссылок:

- [IEK.zip](https://drive.google.com/file/d/18AqNcbkaqrvoLuX9fPsLMleEj7g6CWFb/view)
- [Systeme electric.zip](https://drive.google.com/file/d/1CkzeElvVm_YwkFCofXX1MGBJuUjMecTz/view)
- [Исходное ТЗ](https://docs.google.com/document/d/1Z4faOPlT1t6NMCuJSKKB8-vkZ2LVzGMR0PO9rtZgSnM/edit)

Используйте `POST /api/imports/supplier-bundle/iek` или `/api/imports/supplier-bundle/se`.

Поля multipart: `file` (ZIP), `dry_run=true` для проверки. Для применения нужны **оба** параметра: `dry_run=false` и `replace_supplier=true`.

Сервер распаковывает только XLSX во временный каталог, использует существующий адаптер поставщика и удаляет временные файлы. Поддерживаются вложенные папки архива. Лимиты: ZIP 64 МБ, 100 элементов, 256 МБ внешней распаковки; содержимое одного XLSX — до 256 МБ, всех XLSX — до 512 МБ. Небезопасные пути, повторяющиеся имена и зашифрованные архивы отклоняются.

Это **замена входных данных выбранного поставщика**, включая вручную изменённые продажи, остатки, поставки и правила MOQ. Другие поставщики и история расчётов сохраняются. Срок поставки существующего поставщика сохраняется. Каталог обновляется по кодам; старые товары, отсутствующие в новом комплекте, остаются для исторических ссылок, но их прежние входные записи удаляются. Коллизия кода с другим поставщиком отменяет операцию.

В отличие от универсального импорта, полный комплект не требует `external_id`: строки поставщика заменяются целиком. Привязки incremental-импортов заменённых строк удаляются. После полной загрузки не добавляйте ту же историю продаж повторно через универсальный импорт.

Пример PowerShell после скачивания архива:

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/imports/supplier-bundle/iek -F "file=@IEK.zip" -F "dry_run=true"
curl.exe -X POST http://127.0.0.1:8000/api/imports/supplier-bundle/iek -F "file=@IEK.zip" -F "dry_run=false" -F "replace_supplier=true"
```

API применяет комплект транзакционно. Старый `hackalem ingest` остаётся CLI-инструментом полной перезагрузки обоих поставщиков и очищает все внешние привязки; для отдельных обновлений используйте новые endpoints.
